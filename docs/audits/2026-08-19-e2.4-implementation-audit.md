### M. The absolute-path defect — scoped

**(a) What is machine-dependent.** In `FeatureStackManifest`'s substance the
DEM's absolute path appears **nine times** — once at `dem.path` and once inside
each of the eight `layers[i].dem.path`. Demonstrated with identical DEM

No hostname, username, locale or timestamp enters any substance (the only

`tests/test_covariate_stack.py::test_two_independent_builds_produce_identical_rasters_and_substance`
builds both stacks from **one** `dem_path`, varying only the OUTPUT directory:

```
same dem path, different OUTPUT dir -> content_hash equal: True
different dem path                  -> content_hash equal: False
```

The test varies the axis the manifest does **not** record and holds fixed the
axis it **does**. Its assertion is true; its docstring's claim — "two
independent builds must produce the SAME hash", the property PROVENANCE.md

can observe. This is the coverage-that-isn't shape sitting under the

### N. The mutation-harness rule — scope gap

BACKLOG §3's entry is titled "**Review workflows** must run against a COMMITTED
state or a copy", and its layer (b) reads "a **reviewer** that probes by
MUTATION takes a `cp` copy before its first write and restores by `cp`,
verifying with `cmp`". Two gaps:

1. **Scope.** It binds *reviewers*. The E2.4 §2 incident was the session's own
   harness — a `for f in $FILES` loop that (zsh not word-splitting an unquoted
   scalar) made **no backups**, so the restore was a silent no-op and 16
   mutations accumulated. Nothing in the entry addresses a mutating process
   that is not a reviewer.
2. **Content.** It prescribes restore-by-`cp` with `cmp` verification, but not
   the step whose absence caused the incident: **verify the copy exists and
   matches BEFORE the first mutation.** (A second missing step, learned here:
   verify the mutation actually changed the file — a no-op edit makes the probe
   pass vacuously.)

Both prior instances (E2.2, E2.4 §2) were recovered by **reconstruction**, not
from a verified backup. The entry is still open with trigger "before the next
adversarial review runs"; two have run since, both of which satisfied layer (a)
by committing first.

### O. M42's inertness — independently checked, **confirmed inert**

M42 makes `DesignResult.to_record()` record the splitter's claim instead of the
assertion's measurement. Decisive test — emit the manifest with and without the
mutation:

```
content_hash unmutated : sha256:906579734383adaa2cc90d4
content_hash mutated   : sha256:906579734383adaa2cc90d4
IDENTICAL EMITTED BYTES: True
separation values that differ: 0 of 47
```

Case **(i)**: the mutation genuinely cannot change behaviour. Both values come
from the same pure function on the same coordinates, so they are bit-identical
for any assignment a shipped splitter produces. **Not** a missing test.

One refinement the walkthrough's wording overstates: it says the two are
"provably EQUAL", but the guard admits `np.isclose(rtol=1e-9, atol=1e-9)`. A
**hand-built** `FoldAssignment` recording a value drifted inside that tolerance
is accepted (demonstrated: a 5.0e-10 km drift passes) and would change the
emitted bytes with no observer. No shipped splitter can produce one, so this is
a wording refinement, not a defect.
