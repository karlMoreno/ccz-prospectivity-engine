## §0 — The loop this closes, and how long it stayed open

P2.A (2026-08-09) deferred this field on a stated rule: *"a field with no
consumer is a field nobody has tested the meaning of"*, pairing it with the
trigger *"`acceptance_thresholds` arrives with E2.5's refuse-to-validate

deferral closed **on its own condition**, not on a fresh judgement.

What is worth recording is not that a deferral closed on time. It is **how
close it came to never being noticed as open**:

| when | what was asserted | what was true |
|---|---|---|
| stated **2026-08-14** (E2.X approval), committed **2026-08-18** (`009835e`) | `docs/BACKLOG.md` §2's E2.5 tripwire listed *"Contract 8's loader refusing AUTHORED thresholds"* among the refusals E2.5 would merely ASSEMBLE | no such refusal existed; no slot existed either |
| 2026-08-19, the E2.5 task prompt | inherited the same claim, that the loader *"already refuses an AUTHORED acceptance threshold"* | still false |
| 2026-08-19, the E2.5 approval | recorded the error as **correction drift at a new site** (a task prompt's premises) and corrected §2's *other* conflated sentence | the tripwire bullet — **the actual source** — was left standing |
| 2026-08-19, C8.1 | *(this commit)* builds the refusal and strikes the bullet | the claim becomes true, four days after it was first made |

So the premise was not invented by a prompt: it was inherited from the
BACKLOG, and it survived a correction pass over the very entry that contained
it. The correction fixed the wrong sentence in the right entry. **C8.1 is the
commit that makes the claim true** — and the tripwire bullet is struck rather
than quietly updated, because a premise that was false when written is a fact
about how this repo fails, and silently making it accurate deletes the
evidence.

**Two dates, not one — and the first draft of this table had it wrong.** It
said the premise "was written into the BACKLOG five days earlier", which
conflates the day Karl STATED the tripwire (2026-08-14, the bullet's own
attribution) with the day it ENTERED THE REPO (2026-08-18, `009835e` — one
day before E2.5's commit, `6c6017f`). Caught by `git log -S` on the sentence
rather than by re-reading the sentence. It is the same class the table
documents, produced while documenting it, and it is recorded here rather than
smoothed over: **the check that catches a mis-dated claim is the commit

The general shape, worth more than the instance: a false premise about a

## §1 — The field

```yaml
acceptance_thresholds:
  # ... the comment IS the deliverable (see below) ...
  value: null
```

`model_config_version` **1 → 2**. The bump is real — the shape changed — and
the change is **ADDITIVE**: no existing field's value or semantics moved, so
Track G's re-sync is a **read, not a review**. Recorded in the contract's own
header as a version-history block, and in the contracts README.

**Why the comment carries the weight.** A bare `acceptance_thresholds: null`
tells Isaac nothing about what to put there, so the comment asks the two
questions E2.4 proved are different:

- **(a) what margin over the mean baseline counts as credible uplift, and on
  which metric?** The runner reports `rmse_uplift`, `rmse_ratio`,
  `r2_pooled`, `standardized_rmse`, `coverage_1sigma` per design; a gate must
  name one metric and one number, not "better than baseline".
- **(b) does a model that beats the baseline WITHIN clusters but not ACROSS
  them pass?** With the caveat stated before the question: on this geometry
  the across-cluster comparison **cannot rank estimators at all** (the
  two-fold geometry theorem — fitted range ≤ 13 km against clusters ~991 km
  apart, so kriging reverts to the training cluster's mean and ties the
  baseline exactly). So (b) is really *"is the within-site gate sufficient
  for a claim?"* — a judgement about generalization, not a number to compute.

**And what filling it means, stated where it cannot be missed:** the scores
ALREADY EXIST (E2.4, dated by `scores_first_visible`, with the commit as the
authoritative witness). Any threshold set from now on is **post-hoc for this
dataset, permanently** — in the full sense for kriging, which fits real
coordinates against real y; only weakly for RF, whose covariates are
synthetic noise. The slot does not pretend otherwise: `set_after_scores: true`
is refused by name, and `declared_at:` is compared against
`scores_first_visible`.

Two things are deliberately NOT in the field, each for a stated reason:

- **no `admissible_values` enum** — an enum of acceptable gates would be
  Track E pre-deciding the standard its own work is measured against, the
  same defect as an AUTHORED value one level up;
- **no fixed populated SHAPE** (one expression vs a mapping of the two gates)
  — fixing it would pre-declare a shape nobody has tested the meaning of,
  which is the rule that deferred the whole field in the first place.

## §2 — The loader: three states, two outright rejections

```text
       contract["acceptance_thresholds"]
                    │
         ┌──────────┴───────────┐
         │ field ABSENT         │──► raises. Missing ≠ null. After C8.1 an
         │                      │    absent field means the contract was
         │                      │    EDITED, not that the gate is undecided.
         ├──────────────────────┤
         │ value is None        │──► DeclaredField(None, None, None)
         │  "AWAITING"          │    NOT an error — precondition 6 reads it
         │                      │    and refuses BY NAME. Today's state.
         ├──────────────────────┤
         │ value present        │
         │   ├─ no data_origin  │──► REJECTED: a value cannot arrive
         │   │                  │    unclassified.
         │   ├─ AUTHORED        │──► REJECTED OUTRIGHT, with the asymmetry
         │   │                  │    in the message.
         │   ├─ SYNTHETIC       │──► REJECTED: less real than LITERATURE.
         │   └─ MEASURED/       │──► DeclaredField(value, origin, author)
         │      DERIVED/LIT     │
         └──────────────────────┘
```

**Admissibility is derived, not hand-listed.** `ADMISSIBLE_THRESHOLD_ORIGINS`
is a slice of `ORIGIN_ORDER_MOST_REAL_FIRST` up to and including
`LITERATURE`, so the rule reads *"a gate must be at least as real as
LITERATURE"* and cannot drift from `origin.py`. **Not invented here:** it is
the set precondition 6 already named in prose — inside the AUTHORED branch
C8.1 deleted (§3 below), which read *"it arrives as LITERATURE with a
citation that locates it, or as a MEASURED or DERIVED value with its
evidence"*. The rule was written down before it was enforced; C8.1 turns the
prose into the check, which is why the branch could be REMOVED rather than
merely bypassed. A deny-list of `{AUTHORED}` would have
admitted SYNTHETIC; mutation M2 (below) is what separates the two.

**THE ASYMMETRY, stated in the code because it looks like an inconsistency.**
`target_definition`'s provisional default IS `AUTHORED` (`author: model`) and
that is fine — a wrong TARGET degrades output quality, is recorded, and is
swappable, and the caveat travels with the number. A wrong THRESHOLD does
something else: it silently **becomes the verdict**. Same taxonomy, opposite
admissibility, for a stated reason. Without that note in the raise, the next
reader "fixes" the inconsistency.

**One structural change to the carrier.** `DeclaredField.data_origin` widens
to `str | None`, guarded by a `__post_init__` invariant: **a non-None value
requires a non-None origin**. It is an implication, not a biconditional —
`target_definition` legitimately ships `value: null` WITH an origin, and
enforcing the converse would break that documented state for no stated
requirement. The invariant makes "populated but unclassified" unrepresentable
for any FUTURE accessor; the accessors still refuse first, with better
messages that name the field.

## §3 — E2.5's guard: verified, not rebuilt

**Which change was needed: none to the null handling.** Precondition 6
already had an explicit `declared.value is None` branch — E2.5 wrote it for
the post-slot world before the slot existed. Today it stops taking the
ABSENT route and starts taking the NULL route: the same verdict, one branch
over.

Two changes WERE needed, both small:

1. **The AUTHORED branch was DELETED, not lost.** With the loader rejecting
   AUTHORED, `_check_pre_registered_threshold` can no longer receive an
   AUTHORED `DeclaredField` — `acceptance_thresholds()` is the only way in,
   including through the `contract` test seam. Leaving the branch would have
   been unreachable code with a test that *appeared* to exercise it:
   coverage-that-isn't, the class CLAUDE.md tracks. One rule, one site.
2. **The `except` wrapper widened** from "no pre-registered gate existed" to
   "no **admissible** pre-registered gate existed", because two different
   loader refusals now land there, and it inlines the loader's own message so
   the refusal still SAYS why.

**The verdict on today's data did not change.** The committed E2.4 run,
through the guard, before and after — both claim-eligible designs:

| | before | after |
|---|---|---|
| PASSED | the 5 non-threshold preconditions | **identical** |
| FAILED | `{PRE_REGISTERED_THRESHOLD}` | **identical** |
| `eligible` / `is_scientific` | False / False | **identical** |
| reason | *"no pre-registered gate existed … has no acceptance_thresholds field"* | *"Contract 8 declares acceptance_thresholds explicitly NULL — a declared absence is still an absence"* |

Only the ROUTE moved. That was the property C8.1 had to preserve, and it is
pinned in `test_the_committed_e2_4_run_is_refused_for_exactly_the_honest_reasons`.
