## 1. What normalization.yaml actually says (Contract 7)

Restated from `data/config/normalization.yaml`, confirmed against the engineer of record
before writing code:

| Class | Rule | `observation_or_prediction` |
|---|---|---|
| MASS | pass through if already kg/m²; else `kg_m2 = nodule_mass_kg / sampled_area_m2` | `observed` |
| COUNT | `kg_m2 = nodule_density_m2 * mean_nodule_mass_g / 1000`, **only** if `mean_nodule_mass_g` is present **on the row** (confirmed 2026-07-27 — no `source_queue.yaml`-level lookup exists in the frozen contract) | `observed` |
| COVER | never produces `abundance_kg_m2` — hard rule | `observed` |
| GRID | keeps the compiled value, forces `observation_or_prediction = "compiled"` | `compiled` |
| GRADE | chemistry only, never `abundance_kg_m2` | `observed` |

Screening bounds (`normalization.yaml`'s `screening:` block, TS-6 Table 2), applied
**after** normalization, on **any** evidence class, flagging rather than dropping:

```
abundance_kg_m2: 0.0 – 45.0   (0 = valid/barren)
mn_pct:          10.0 – 45.0
ni_pct:          0.3  – 2.0
cu_pct:          0.2  – 2.0
co_pct:          0.02 – 0.5
```

Flag field: `qa_status` (schema enum `pending|pass|fail|flagged`) → set to `"flagged"`.

## 2. Architecture — Strategy + Registry

```
    native adapters ──► RawRecord ──► NormalizerRegistry.normalize(record)
                                            │
                                            │ 1. look up by evidence_class
                                            ▼
                              ┌─────────────────────────────┐
                              │     AbundanceNormalizer (ABC)   │   STRATEGY
                              │     .normalize(record)          │   (normalizer.py — unchanged)
                              └─────────────────────────────┘
                                ▲       ▲       ▲       ▲       ▲
                            ┌──────┐┌───────┐┌───────┐┌──────┐┌───────┐
                            │ Mass ││ Count ││ Cover ││ Grid ││ Grade │   (all new, E1.2)
                            └──────┘└───────┘└───────┘└──────┘└───────┘
                                            │
                                            │ 2. apply_screening(record)   <- Contract 7
                                            ▼                                 screening bounds,
                              record with abundance_kg_m2 (or not)            cross-cutting,
                              + qa_status flagged if out of bounds            NOT per-class
```

`NormalizerRegistry` is a **Registry** (not one of CLAUDE.md's four named seams itself —
a companion to Strategy): it maps `evidence_class -> AbundanceNormalizer` so
`IngestionPipeline` never branches on `evidence_class`, and it owns the screening step so
each `*_normalizer.py` stays single-purpose (only knows its own formula). Adding evidence
class #6 later is one `.register(...)` line in `build_default_registry()` — no pipeline
change.

## 3. Per-file explanation

| File | What it is |
|---|---|
| `engine/prospectivity/ingestion/mass_normalizer.py` | `MassNormalizer` — passthrough if `abundance_unit_original` is `kg_m2`/`kg/m2`, else `nodule_mass_kg / sampled_area_m2`. |
| `engine/prospectivity/ingestion/count_normalizer.py` | `CountNormalizer` — `nodule_density_m2 * mean_nodule_mass_g / 1000`, row-only gate on `mean_nodule_mass_g`; otherwise leaves `abundance_kg_m2` untouched (`None`). |
| `engine/prospectivity/ingestion/cover_normalizer.py` | `CoverNormalizer` — always sets `abundance_kg_m2 = None`. Hard rule, no branching. |
| `engine/prospectivity/ingestion/grid_normalizer.py` | `GridNormalizer` — copies `abundance_value_original` into `abundance_kg_m2` as a prior, forces `observation_or_prediction = "compiled"` unconditionally (even if a row arrived mislabeled `"observed"`). |
| `engine/prospectivity/ingestion/grade_normalizer.py` | `GradeNormalizer` — always sets `abundance_kg_m2 = None`; carries `mn/ni/cu/co_pct` through untouched. |
| `engine/prospectivity/ingestion/normalizer_registry.py` | `NormalizerRegistry` (register/normalize/assert_complete), `apply_screening()`, `build_default_registry()` — the real production registry (all 5 classes, `assert_complete()`-checked). Loads screening bounds from `data/config/normalization.yaml` at runtime (via a small `pyproject.toml`-anchored repo-root finder) rather than duplicating the numbers in Python. |
| `engine/prospectivity/ingestion/pipeline.py` | **Mechanical change only.** `IngestionPipeline.__init__`'s `normalizers` parameter is now typed `NormalizerRegistry` instead of a bare `dict[EvidenceClass, AbundanceNormalizer]`; `_normalize()` now calls `self._normalizers.normalize(record)` instead of doing the evidence-class lookup itself. The fetch→adapt→normalize→validate→dedup→append sequence is unchanged. |
| `tests/conftest.py` | `NORMALIZERS` is now built by `_build_fixture_normalizer_registry()` (wraps the existing E0.4/E0.5 `Fixture*Normalizer`s in a `NormalizerRegistry`) instead of a bare dict — required so `IngestionPipeline` can call `.normalize()` on it. GRADE is deliberately left unregistered there: the fixture sources never emit a GRADE row. |
| `tests/test_normalizers.py` | New. One test per class's formula + the required regression/completeness tests (below). |

No change to `normalizer.py` (the ABC), any `SourceAdapter`, `specification.py`, or dedup.

## 5. How to hand-check this manually

```python
from engine.prospectivity.ingestion.normalizer_registry import build_default_registry

registry = build_default_registry()
registry.assert_complete()  # raises if any evidence_class is unregistered

record = {
    "evidence_class": "MASS",
    "nodule_mass_kg": 2.5,
    "sampled_area_m2": 0.25,
    "qa_status": "pending",
}
print(registry.normalize(record))
# -> abundance_kg_m2=10.0, derivation_formula="...", qa_status="pending" (in-bounds)
```

Try `nodule_mass_kg=20.0` with the same area (80 kg/m²) and watch `qa_status` become
`"flagged"` — that's the screening step, not a bug.

## 6. Deliberately missing / not yet wired

- **No corpus-builder entry point.** Nothing yet calls `build_default_registry()` in
  production — only `tests/conftest.py`'s fixture registry is exercised end-to-end. That
  starts when a real `IngestionPipeline` is run against real sources (later E1.x task).
- **GRADE's join logic** (station_id, else cruise+event+coords within
  `join_tolerance_km`) is explicitly *not* `GradeNormalizer`'s job — that's corpus
  assembly, not per-record normalization. `join_tolerance_km` is still
  `null # [GEOLOGY — ISAAC]` in `normalization.yaml`; unresolved, not touched here.
- **`mean_nodule_mass_g_source`** in `normalization.yaml` is still `null # [GEOLOGY —
  ISAAC]`. We confirmed E1.2's `CountNormalizer` uses the row-only value; the
  source-level aggregate this placeholder gestures at (e.g. an SO268-derived constant
  applied to a *different* source's COUNT rows) is not implemented and would need a
  `source_queue.yaml` contract change (a new field) if it's ever wanted.
- **Rounding.** Neither `MassNormalizer` nor `CountNormalizer` rounds the computed
  `abundance_kg_m2` (unlike the old `Fixture*Normalizer`s, which round to 3dp for
  readability) — normalization.yaml doesn't specify a precision rule, so none was
  invented.
