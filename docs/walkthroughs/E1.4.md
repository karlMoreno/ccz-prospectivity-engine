## 2. Architecture

```
    covariates.yaml (Contract 3, v3)          data/corpus (E1.3, unchanged)
        │ loaded, never duplicated                      │
        ▼ (_contract.py)                                │ (plot only)
    build_default_registry() ─── REGISTRY ──────┐       │
      · every enabled entry has exactly one      │       │
        implementation (completeness, mirrors    │       │
        NormalizerRegistry.assert_complete)      │       │
      · contract recipe_version == class         │       │
        RECIPE_VERSION, or refuses to build      │       │
                                                 ▼       ▼
    DemGrid (dem_grid.py) ──────────► CovariateRecipe (x8) ──► plot_stack.py
      · THE home of CRS strategy A     STRATEGY + TEMPLATE       (deliverable,
      · values + per-row dx_m, dy_m    METHOD:                    dev-only
      · cell_size_ns_m: the scalar       build(grid):             matplotlib)
        for window resolution            resolve windows ──► window.py
                                          -> compute        (THE metres->cells
                                          -> provenance      conversion; clamps
                                                 │           to minimum + says so)
                                                 ▼
                                        build_covariate_stack (stack.py)
                                          8 GeoTIFFs + provenance.json
                                          (byte-deterministic, E1.3 CSV bar)
```

Pattern notes, in the code where they're used: `CovariateRecipe` is
**Strategy** (one interchangeable class per contract recipe) plus **Template
Method** (`build()` fixes resolve→compute→provenance so no recipe can skip
provenance or resolve windows its own way); `CovariateRegistry` is the same
**Registry** companion `NormalizerRegistry` is, keyed by covariate name.
Phase 0's `features/__init__.py` sketched "a plain callable, no hierarchy" —
superseded by your E1.4 instruction precisely for the registry's completeness
guarantee; `engine.py`'s `feature_builder` callable seam is unchanged and
`registry.build_all` is what plugs into it in Phase 2.

## 6. Deliberately missing / out of scope

- **Covariate extraction at sample locations** — Phase 2's training matrix,
  its own reviewed task (per instruction).
- **Real GEBCO** (G1.1, Checkpoint 1). Everything here runs on the labelled
  synthetic DEM; the metre windows resolve unclamped only on the real DEM.
- **Option B** (sediment_type, surface_chlorophyll, ccd_minus_depth,
  bathymetric_regime): disabled, unimplemented, tested to stay that way.
- **Anisotropy correction in windows**: resolved windows use the N-S cell
  size; the E-W physical span differs ≤~3% at study latitudes. Recorded in
  provenance (`crs_strategy`), deliberately not corrected.
- **TerrainSource wiring**: `DemGrid.load(path)` takes a path directly;
  connecting it behind the `TerrainSource` Strategy (and `TerrainLayer`
  metadata) happens when `ProspectivityEngine.run()` is assembled in Phase 2.
- The clamped windows on the synthetic DEM mean the windowed covariates are
  effectively 3×3/annulus-2 until Checkpoint 1 — honest, recorded, expected.
