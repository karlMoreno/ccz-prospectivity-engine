## 2. What the audit found

### 2.1 Corpus-level rules were asserted *through* the model that enforces them

`test_observation_schema.py` loads the corpus via `Observation(**row)` — the
same class whose validator forbids COVER-with-abundance. A violating row on disk
makes the **loader raise**, so those assertions can never observe a violation;
they assert what construction already guaranteed.

Verified by mutation, and the nuance matters: writing `abundance_kg_m2 = 1.0`
into `CoverNormalizer` did **not** fail any test, because the pipeline crashed at
`_validate()` and never rewrote the CSV. The pipeline structurally cannot produce
this violation — good news, and also why the corpus-level test's real threat model
is *a writer that bypasses `Observation`*. Mutating the CSV directly (the actual
threat) fails the new raw tests precisely; the old tests also fail, but all four
report the same generic `ValidationError` at the loader line rather than naming
the broken rule.

**Fixed** by [`test_corpus_invariants.py`](../../tests/test_corpus_invariants.py),
which reads the CSV as raw strings.

### 2.2 Three-way evidence-class agreement was missing a leg

Code↔registry was tested; **schema↔code was not**. Adding `SEISMIC` to the
contract's enum would have passed the whole suite. Fixed at
[`test_corpus_invariants.py:109`](../../tests/test_corpus_invariants.py#L109).

### 2.3 Reachability was untested

Registry completeness proves every class *has* a normalizer, not that any adapter
*produces* one. GRID and GRADE are registered but unreachable today — dead code
that looked covered. Now asserted explicitly, with the reason for each stated in
`DELIBERATELY_UNREACHABLE`, so wiring `[18]`/`[19]` forces a deliberate update.

### 2.4 Mutations run

| Mutation | Result |
|---|---|
| `CoverNormalizer` sets `abundance_kg_m2 = 1.0`, corpus rebuilt | **No test failed** — the rebuild itself crashed at validation and never wrote the CSV. Reported, not hidden (§2.1). |
| COVER row given `abundance_kg_m2 = 7.5` directly in the CSV | `test_raw_corpus_no_cover_row_carries_an_abundance_value` **FAILED** ✓ |
| COUNT row's `mean_nodule_mass_g` blanked in the CSV | `test_raw_corpus_count_rows_carry_abundance_only_with_a_recorded_mean_mass` **FAILED** ✓ |
| GRADE unregistered in `build_default_registry()` | three-way agreement + reachability **FAILED** ✓ |
| COVER mapping removed from `[01]`'s builder | reachability + adapter-declaration **FAILED** ✓ |

All reverted; `git status` clean apart from the intended additions.

  adapter constructor), so it is not unguarded — but the *corpus* assertion is

- **`[19]` Washburn's dual-class fan-out (GRID+GRADE in one row) has no test.**

- **GRADE's station join is untested because it doesn't exist** —
  `join_tolerance_km` is unresolved geology input. GRADE rows pass through
  unjoined by design.
- **Intra-batch duplicates.** Dedup only compares a candidate against the corpus
  so far; two duplicates inside one adapter's own fetch would not catch each
  other. No wired source has that shape. BACKLOG §3.
- **Rests on a single test, named here rather than claimed as depth:**
  end-to-end survivorship order-independence
  ([`test_corpus_builder.py:128`](../../tests/test_corpus_builder.py#L128)) and

  ([`test_corpus_manifest.py:141`](../../tests/test_corpus_manifest.py#L141)) are

  (`Field(ge=0)` raises first), so D6's negative-area branch is demonstrable only

## 4. Follow-ups (2026-07-29) — and the bug the second one found

### 4.1 Specification combinators deleted

`_And`/`_Or`/`_Not` + `&`/`|`/`~` removed (zero production composition sites);
`test_specification_combinators.py` deleted (−3 tests). ABC kept — the pipeline
depends on that interface. Full rationale now lives in
[`specification.py`](../../engine/prospectivity/ingestion/specification.py)'s own
docstring, so it survives independently of `PATTERNS.md`.

### 4.2 The idempotency test found a real production bug

Item 2 was specified as a *guard* for the fragility that motivated item 1. It
turned out to be a *detector*: written against the real code, it **failed
immediately**. Two independent causes:

1. **`_merge` re-appended the provenance link.** The gap-fill is naturally
   idempotent (it only fills a `None`); the `notes` append was not. Merging the
   same pair twice duplicated the link text.
2. **A row matched itself on re-run.** On a second `build_corpus()` against the
   same corpus, a candidate matched the very row it produced last time, and the
   merge recorded `"duplicate of <its own source_record_id>"` — corrupt
   provenance, not just noise.

**This reached production.** `build_corpus()` documents itself as safe to re-run,
and it is — for row *count*. Measured before the fix: two runs left 108 rows but
grew row 0's notes from 1 provenance link to 3.
`test_idempotency_rerunning_against_the_same_corpus_adds_nothing` passed
throughout, because it compared only the length and the id list — a test whose
name claimed more than it checked.

**Fixes:** an `already_linked` guard in `_merge`, and a same-record short-circuit
in `is_satisfied_by` (identical `source_id` + `source_record_id` means the same
record is being re-offered, not a duplicate pair). Both in
[`dedup_rules.py`](../../engine/prospectivity/ingestion/dedup_rules.py).

**Verified:** `build_corpus()` run three times now leaves every field of every
row identical. The corpus-level idempotency test was **strengthened** to compare
`model_dump()` for all rows across two extra runs — it is the test that should
have caught this.

| Mutation | Result |
|---|---|
| `already_linked` guard removed | new idempotency test **FAILED** ✓ |
| same-record short-circuit removed | strengthened corpus idempotency test **FAILED** ✓ |
| `from_terrain_layer` hash verification removed | lying-source test **FAILED** ✓ |

### 4.3 `TerrainSource` wired, not deleted

The diagnosis was sharper than "unused": **the seam was never absent.**
`ProspectivityEngine._ingest` already called `terrain_source.load(study_area)`
and passed the `TerrainLayer` to `feature_builder`; what was missing was any way
for `features/` to consume a layer, so E1.4 went around it with
`DemGrid.load(path)`.

Added `DemGrid.from_terrain_layer(layer)` (primary — matches what the engine
already produces) and `from_terrain_source(source, study_area)` (convenience).
The bridge **verifies the layer's reported `content_hash` against the SHA-256 of
the bytes it actually read**, so a source cannot seed provenance with a hash it
didn't compute. `DemGrid.load(path)` stays as the low-level reader the bridge
delegates to.

Both `content_hash="sha256:synthetic-fixture"` placeholders are gone —
`FixtureTerrainSource` and, in the same pass, `FixtureTS6Reference`, since
leaving one of two identical fakes would have reintroduced the problem at
Checkpoint 3. Being synthetic is recorded in the layer's name, never by faking a
hash.

6 new tests in [`test_dem_grid.py`](../../tests/test_dem_grid.py): the seam
round-trip, real-hash-not-placeholder, hash-mismatch rejected, pathless layer
rejected, and the layer bridge.

**Checkpoint 1 is now a substitution at the seam:** implement
`GEBCOTerrainSource`, inject it, change nothing in `DemGrid` and nothing in any
recipe.
