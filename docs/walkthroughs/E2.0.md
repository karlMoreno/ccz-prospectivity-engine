## E2.0-1 — `CorpusCsvSampleSource`

**What this closes.** `SampleSource` was a Phase-0 Strategy with zero
production implementations (PATTERNS.md §3.2; BACKLOG §3 since E1.3). The
MASS-only rule reached production only through
`Observation.is_training_eligible()` called ad hoc — the corpus manifest and
`plot_stack` each filter the corpus list directly — and every `SampleSource`
caller was a test double. E2.0-2/-3 need a production "give me the training
rows" seam; this is it.

```
  data/corpus/master_observations.csv          (108 rows, MASS/COUNT/COVER)
        │  pd.read_csv → NaN→None → Observation(**row)
        ▼                             └─ Contract-1 validation per row: a
  CorpusCsvSampleSource (STRATEGY impl)          forbidden row raises at load
        .load_observations()  ← the abstract hook, and ALL this task adds
        │
        ▼
  SampleSource.get_training_samples()  ← inherited; the gate lives on the
        │                                 ABC + Observation, NOT here
        ▼
  35 training-eligible MASS rows       (== manifest.training_eligible_count)
```

**The design decision, and its refusal:** the eligibility gate is deliberately
NOT reimplemented, not even as a private helper. `get_training_samples()` is
inherited unchanged, and eligibility is decided by
`Observation.is_training_eligible()` alone — two implementations of one rule
is how they drift (the prompt's words, and E1.2's normalizer-vs-schema
history's lesson). The one thing the class does is the hook: read, NaN→None,
validate each row through `Observation`. That last step means the production
read path applies the same evidence-class discipline as ingestion — a
hand-edited CSV row violating Contract 1 fails loudly at load, before any
consumer sees it.

**§1(a), answered before the guard was written:** each layer's provenance
DOES carry its own full `dem` dict — but one stack copies one
`DemGrid.provenance()` into all 8 layers, so a single stack is
**structurally incapable of disagreeing with itself**. The guard is
therefore built against the real threat: an extraction assembled from
layers of DIFFERENT stacks (the Checkpoint-1 synthetic→GEBCO transition) or
a stack whose provenance went stale against its rasters. Per §1(b), the
guard tests and mutation use exactly that shape — two stacks at different
resolutions (and two at equal resolution, different bytes) combined into
one extraction. Honest limit, stated in the module docstring: a
record-checking guard checks records — an array swapped under a copied
provenance dict is undetectable in principle; the shape check catches the
detectable subset.

**Sampling: nearest-cell, decision made, alternative recorded in the code
comment** (bilinear declined: it propagates the nan_border inward a cell
and invents values between cells — compounding two approximations and
making the recorded provenance less exactly true of the number). One
function with a recorded `sampling_method`, deliberately NOT a PointSampler
Strategy (PATTERNS.md §3 ceremony standard); the recorded field is what
makes a future swap auditable.

**The shared-cell structure — the headline finding of this task:**

```
  35 stations on the 0.1° synthetic DEM (~11 km cells) → 4 distinct cells
    eastern cluster (21 stations):  2 cells, groups 14 + 7
    western cluster (14 stations):  2 cells, groups 7 + 7
    shared_cell_count = 35  (every station shares its cell)
```

Stations sharing a cell have IDENTICAL X and DIFFERENT y — irreducible
error no covariate model can beat. Computed against the real abundance
values, the within-cell variance is 333.7 of 512.2 total SS, so **the
maximum achievable R² for ANY covariate-driven model on this fixture is
0.348**. That is a computable ceiling on Phase-2 performance before any
model runs: a model at or above it before Checkpoint 1 is a bug or a
fixture artifact, and honest results will sit far below it (the covariates
are synthetic noise anyway). Effective sample size for anything
covariate-driven: 4 distinct X rows, not 35. On real GEBCO (~460 m at
13°N) the stations separate. These numbers are literal-pinned by
`test_real_corpus_occupancy_is_4_cells_with_groups_14_7_7_7`, to be
re-reported at Checkpoint 1.

**The border situation, reported before anything downstream decides:** on
today's fixture (corpus bbox + 0.5°, ≥5-cell margin) **zero** of 35
stations hit a NaN border cell — pinned, plus a geometry assertion (every
station's cell ≥5 cells from every edge) that stays meaningful even under
a zero-fill bug. The carry-the-NaN path is therefore exercised only by the
constructed border-station fixture, which is its SOLE observer
(mutation-verified below) and carries the E2.0-1b docstring warning.
Off-raster stations refuse by name rather than flagging — no containing
cell exists, so that is a broken extent (the E1.4 0-of-35 bug class), not
a border case.

**A float-representability finding, kept honest:** the "boundary tie-break
goes east/south" claim is only testable on grids whose cell size is an
exact binary fraction (the edge test uses 0.125°) — on a 0.1° grid a
nominal edge coordinate lands by float rounding. Relatedly, the review
demonstrated our subtract-then-divide arithmetic and rasterio's
inverse-affine `index()` DIVERGE at nominal boundary decimals (lat 14.6 on
the 0.1° frame resolves one row apart) while agreeing on all interior
points (0/200,000 probes) and all 35 real stations (nearest sits ~0.05
cells from an edge). Kept as our own arithmetic deliberately — delegating
to rasterio would make the comparison test a tautology — with the caveat
now stated in `_nearest_cell`'s docstring; the first corpus station on a
nominal boundary fails the comparison test loudly, which is correct: at
that point either answer is defensible and a human should pick.

## E2.0-3 — TrainingMatrix and its provenance

**What this closes.** The matrix E1.4 deferred exists, with the one decision
that defines what the model predicts — the target — carrying identity in
the provenance chain for the first time.

```
  CorpusCsvSampleSource ──► 35 Observations, sorted by source_record_id
        │                        │
        ▼                        ▼
  DemGrid + 8 layers ──► extract_covariates_at_stations  (E2.0-2 guard inside)
        │                        │  NaN anywhere? ──► REFUSE by name
        ▼                        ▼
  Contract 8 target ──► TrainingMatrix (X 35×8 · y 35 · coords 35×2 · ids)
  (DeclaredField:            │              all arrays read-only
   value + origin)           ▼
                   TrainingMatrixManifest          ← the FOURTH artifact
                     upstream {corpus, feature_stack}
                     target value+origin · sampling_method
                     shared_cell_count · cell_groups · matrix_sha256
                     data_origin = combine(corpus, stack)   COMPUTED
```

**y through the contract, not the code.** `assemble_training_matrix` reads
`target_definition()` — the DeclaredField, value AND origin — and maps it
through an exhaustive dispatch (`{"total_as_published": "abundance_kg_m2"}`)
with an explicit raise: a new admissible value arrives via Contract 8 WITH
its assembly rule, never by improvisation. The manifest records value,
origin, and author together, so the AUTHORED→LITERATURE promotion (Isaac's
citation arriving) legitimately changes the artifact's `content_hash` — a
property asserted through real assembly (same `matrix_sha256`, different
identity).

**NaN policy — REFUSE, decision made** (alternative recorded in the module
docstring): a matrix with a hole is a matrix whose extent question has not
been answered. On real GEBCO a station near the raster edge is a thing to
KNOW ABOUT and fix — not a row that quietly vanishes from n=35, where losing
two stations is a 6% loss that would never show as an error.
Exclusion-with-a-record was considered and declined: it converts an extent
defect into a bookkeeping entry, and flag-never-drop elsewhere flags rows
that stay IN the data — an excluded matrix row is dropped by another name.
Zero real stations hit NaN today, so the refusal is sole-observed by the
constructed border fixture (docstring warning, mutation MU1 below).

**The fourth artifact, and why** (class docstring carries the full
argument): corpus hash and stack hash are both INVARIANT to the target, so
two matrices built on different y would present identical
`upstream_hashes` — without a matrix-level record the target has no
identity in the chain. Fold-into-RunManifest was considered and declined:
matrix↔run is 1:1 only by convention, and PROVENANCE.md separates artifacts
by LIFETIME. `matrix_sha256` (canonical bytes of ids/names/X/y/coords) is
recorded IN the manifest, so `content_hash` covers the actual numbers, not
only their description. `model_config_version` enters `contract_versions`
here — the matrix is Contract 8's first consumer. PROVENANCE.md updated to
four artifacts in this commit, along with artifact.py's docstring, the
provenance package listing, and the completeness tests
(`test_provenance_artifact.py` now iterates all four).

**The watermark derives — with one stated divergence from `dem_watermark`.**
`matrix_watermark` keys on the COMPUTED origin, default-ON: clean iff
MEASURED or DERIVED; SYNTHETIC/LITERATURE/AUTHORED/undeclared stamp; unknown
raises. The divergence: `dem_watermark` stamps DERIVED, because for a
DECLARED INPUT DEM, "derived" means the terrain was not actually measured.
For a COMPUTED matrix origin, DERIVED is the intended Checkpoint-1 clean
state — combine(MEASURED corpus, DERIVED-from-MEASURED features) IS
DERIVED, and stamping it would watermark every legitimate GEBCO matrix as
"illustrative only". Keying on the computed origin rather than the DEM
declaration alone also keeps a synthetic CORPUS stamped under a real DEM —
the hole a DEM-only rule would leave. Recorded in both helpers' docstrings
so nobody "unifies" them wrongly. Today's fixture: origin SYNTHETIC,
watermark present; the MEASURED-stack fixture: origin DERIVED, watermark
gone — the direction P2.0c's SYNTHETIC-only fixtures could not observe,
now a test.

**The finding of the phase — the ceiling, and its scope.** On the 0.1°
synthetic DEM the 35 stations occupy **4 distinct cells** (eastern
21-station cluster: 14+7; western 14: 7+7; every station shares its cell).
Stations sharing a cell have identical X and different y, so within-cell
variance (333.7 of 512.2 total SS) is irreducible: **the maximum achievable
R² for any covariate-driven model on this fixture is 0.348**, recomputable
from the manifest's `cell_groups` + y and pinned in the suite.

The ceiling binds COVARIATE-DRIVEN models only. With 4 distinct cells the
design matrix has 4 distinct rows — rank ≤ 4 against 8 covariates — so
random forest is bound by it, and RF importance on this fixture is
arithmetic over 4 examples. **Ordinary kriging is NOT bound: it predicts
from COORDINATES, which remain distinct per station.** Consequence for
reading E2.4's comparison table: if kriging beats RF on this fixture, the
honest explanation is not "kriging is better" — it is that RF fights a
0.348 ceiling kriging never sees. This asymmetry disappears at Checkpoint 1
as the cells shrink and X re-separates. (On record now, before E2.1–E2.4
produce a single number; re-report per BACKLOG §3's Checkpoint-1 item.)
