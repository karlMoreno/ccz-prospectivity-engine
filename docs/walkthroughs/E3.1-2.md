## §1 — Commit 1: the grid is inherited, never chosen

Same extent, cell size, transform and CRS as the stack, so predicting happens
on the covariates' **native grid**: no resampling, and no interpolation
between the values E1.4 recorded and the values a model predicts from.

Measured on the fixture stack:

| | |
|---|---|
| grid | 100 × 34 @ 0.1°, lon [−126.5, −116.5], lat [11.3, 14.7] |
| cells | **3,400** total · **2,880** predictable · **520** masked |
| per-layer NaN | depth 0 · six windowed recipes 264 each · BPI 520 |

**The extent is a fixture's**, and the module docstring says so rather than
letting a reader infer a configured domain — there is no production extent
configuration in this repo (E3.0 §2).

**The mask is flag-never-drop:** any covariate NaN makes a cell undefined,
masked and counted, never zero-filled. The layers' NaN footprints differ,
which is what lets the mask test separate "any layer" from a wrong single
layer. *(The union happens to equal BPI's set, since its 2-cell ring contains
the 1-cell rings — recorded in the test, because the docstring's first draft
claimed more than the assertion checks.)*

**Mutations 6/6:** mask from the first layer only; mask inverted to all-NaN;
cell corners instead of centres; layers in directory order; the one-grid
check removed; arrays left writeable.

## §2 — Commit 2: the builder, and one prediction that failed

Cell count reported before building, as required: **3,400 / 2,880 / 520**.
Routing is by declared `input_kind` — coordinates to kriging, covariates to
RF — never by name.

### E3.0 §4(b) CONFIRMED

| measurement | value |
|---|---|
| predictable cells within **0.5 kg/m²** of the training mean | **99.62%** (2,869/2,880) |
| cells within 0.01 of the far-field variance ceiling | **97.57%** |
| cells within one fitted range (21.611 km) of a station | **34** — the same 34 E3.0 derived |

Kriging's surface spans [17.866, 20.454] around a training mean of 19.531.
It does not return the mean *exactly* anywhere (0 cells within 0.001), which
is the honest refinement: the far field is *within half a kg/m²* of the mean,
not identical to it.

### E3.0 §4(a) CONTRADICTED — investigated, and it is not a builder bug

| | predicted (E3.0) | measured |
|---|---|---|
| value bound | [15.143, 21.657] | **[15.091, 21.681]** — outside at both ends |
| distinct values | "order 10⁰–10¹ plateaus" | **~1,842** |

Two steps of E3.0's reasoning are wrong:

1. **`mu` is quantile-forest's weighted mean of the POOLED LEAF SAMPLES** —
   individual training y values — not an average of the four cell means
   (`quantiles="mean", aggregate_leaves_first=True, weighted_leaves=True`).
2. **Under bootstrap resampling a leaf holds a resampled SUBSET** of a cell's
   stations, whose mean is not that cell's mean.

**The entailed bound is [min(y), max(y)] = [11.6, 26.8]**, which the surface
respects. Both halves are now pinned as tests so the refuted bound cannot be
"restored" by a future reader who remembers E3.0 and not this.

### The targeted test, and both halves of its demonstration

Only **34 of 2,880** predictable cells can show interpolation, and a 200-cell
uniform sample contains **one** of them. So any assertion about variation,
near-data exactness or variance growth is evaluated at those 34 cells, and the
docstring says why.

The prompt predicted a mean-everywhere mutation would slip past a uniform
sample. **It does not** — measured: uniform max|mu−mean| is 0.3183 real vs 0.0
mutated, so a uniform check catches it too. **The blindness is real on the sd
half**: clamping sd to its far-field ceiling is invisible to a uniform probe
because 97.57% of cells already sit there. The targeted test catches both.

### Mutations 7/7 — two needed work

| # | mutation | outcome |
|---|---|---|
| M1–M4, M7 | cherry-pick; routing ignores the declaration; masked cells zero-filled; wrong-length refusal removed; chunking perturbs values | caught immediately |
| **M6** | `n_sd_zero` hardcoded to 0 | **SURVIVED** — every real count is 0, so the test could not tell the computation from the constant (the E2.0-2 `shared_cell_count` degeneracy). Fixed with a constructed 7-zero fixture; the original test now states in its docstring that it cannot separate them |
| **M5** | kriging's prediction → the training mean | caught by exactly the targeted test |

### The builder does not re-check the paired-uncertainty rule

The first draft did, and the ABC's own refusals exposed it as unreachable:
`Estimator.predict()` is a final Template Method already refusing non-pairs,
None members, shape-mismatched pairs, non-finite sd and negative sd.
Repeating them would have been coverage-that-isn't with tests that appeared to
exercise it — the defect C8.1 removed from the claim guard. **What the builder
does own** is the one check the ABC cannot make: that the pair has one entry
per cell *requested*, since only the caller knows how many it asked for.

## §3 — Commit 3: the writer, and three carriers

Written with the **GDAL COG driver** (no dependency). Asserted: driver,
`tiled`, `block_shapes`, `overviews`, CRS, transform, dtype, nodata.
**No COG-ness is claimed** anywhere, and a test asserts the tags never contain
the word. At 100 × 34 the driver emits **no overviews** — measured, recorded,
not a defect.

| carrier | what it holds | mutation |
|---|---|---|
| **1 — GeoTIFF tags** | computed origin, watermark, `publishable`, the failing preconditions BY NAME | tag removed → caught |
| **2 — sidecar** | the same facts beside the file, plus grid identity and the surface summary | sidecar not written → caught |
| **3 — E2.5's guard** | consulted at write time; ineligible ⇒ written but MARKED | verdict ignored → caught; preconditions un-named → caught |

Plus two laundering mutations: hard-declaring the origin MEASURED, and
bypassing `combine_origins`. Both caught. **7/7 overall.**

**GDAL drops empty tags**, so a clean surface would read back with the
watermark tag *absent* — indistinguishable from a file written before the tag
existed. Both tags carry explicit `none (...)` sentinels instead.

### The limit on "per surface", measured

The task asked for a verdict per surface. `evaluate_claim` is keyed on
`(RunManifest, design)`; **four of its six preconditions are properties of the
RUN** and the other two of a **DESIGN**. None is a property of an
**ESTIMATOR**, so today's guard cannot differ between kriging's surface and
RF's. The writer's signature takes one verdict per surface so the shape is
expressible when the guard gains that granularity — a caller passing the same
verdict to every surface is reporting the truth as the guard computes it.

### The audit probe found a real defect in my first draft

Staged under `data/`, `test_data_origin_audit.py` **does** see the sidecar,
and refused it by name: *"SYNTHETIC without a generator import path"* and
*"without a recorded seed"*. The sidecar now carries both, and `_seed_of`
returns `None` honestly rather than fabricating a `0` that would satisfy the
audit while naming a seed nothing used. Stripping the declaration makes the
sidecar UNCLASSIFIED — both directions confirmed, as C8.1 did.

**Two findings remain, BACKLOGged rather than papered over** (`docs/BACKLOG.md`
§3): the `.tif` rasters are UNCLASSIFIED because binary files carry no in-file
marker, and a **SYNTHETIC-by-inheritance** surface cannot satisfy the *seed*
half of SYNTHETIC's evidence rule when its estimator has no seed — kriging is
deterministic and records none.

## §4 — What is NOT done, and why

**The `_compare_to_ts6` type reconciliation.** The prompt asked commit 1 to
decide it, with the instruction to STOP if the two answers pull apart. **They
do**, and the collision is visible in a field:

- `RunManifest.ts6_agreement` is **singular** (`TS6Agreement | None`);
- `TS6Agreement` is `extra="forbid"` and carries **no estimator field**, so it
  cannot even self-identify which surface it describes;
- the registry produces **one surface per estimator**.

So a signature taking one surface forces E3.3's "which estimator" answer by
accident, and a signature taking a mapping cannot be recorded by E3.4 without a
Phase-0 shape change. `compare_to_ts6` is therefore **untouched** — still
raising `NotImplementedError` — and the builder produces a **mapping**, which
is a type that can express "all of them" without deciding which.
