**The emitter's job, in one sentence: recompute, compare, refuse by name,
then say what it could not verify.** Each link — corpus manifest substance,
stack manifest substance, matrix arrays, benchmark raster bytes, every
written raster (values re-read and compared to the in-memory surface; tags
compared to the grid and the estimator) and sidecar (summary compared to
the surface and the grid) — is recomputed and compared against EVERY record
of the same fact (`_require_equal` names each disagreeing record). Every
cross-validated estimator must reach a surface, a file and an agreement;
every executed design must carry a verdict; the surface origin is
recomputed with `combine_origins` and compared to what the writer recorded
(the laundering direction, by name).

**The limit, in the output.** `provenance_chain` says per link what was
recomputed and whether it is verifiable OFF the machine that wrote it —
only the corpus is — and `CHAIN_LIMIT_NOTE` travels with every manifest.
**Measured here for the first time: the path-hash limit reaches 9 of the 10
output files** — every raster (tags) and every provenance sidecar
(`grid.identity()`); not `data_origin.yaml`, which quotes no hash. The same
`SurfaceResult` written against a stack built from the same DEM bytes at a
different path is a different file (values `np.array_equal`; bytes not). The
test pins the DEFECT'S PRESENCE on purpose: when BACKLOG §3's fix lands it
goes red and the chain block's claim must change in the same commit.

### §4a — the fourth commit: the scope counted, and the count corrected me

The prompt's §4 suggested the limit's scope be MEASURED rather than
asserted — "which recorded hashes are path-dependent, counted". Measuring
it (distinct sha256 values present in one tree's manifest and absent from
the other's, `content_hash` excluded) gave **11**, where commit 1's block —
"every output file" — implied 12. The twelfth, `data_origin.yaml`, carries
origin, generator and seed/basis and no hash at all. So the emitter now
TESTS each written file's bytes for the stack hash at emission and records
`provenance_chain.path_dependent_hashes`: `count` (11), `values` (each
moving hash and every JSON path it is recorded at), `independent`
(`["data_origin.yaml"]`). Two tests pin `count` against the measured
two-directory difference — one at the extension level, one at whole-run
level — and both go red when the fix lands, which is what a pinned limit
is for. Convention 5, in its own words: the correction was verified against
the measurement, and the measurement corrected the correction.

**The test this commit was missing until it was written.** Every refusal
test made two RECORDS disagree — which a COPYING emitter would also catch.
Nothing separated "recomputed from the artifact" from "copied from a record
that happened to be right". The separating fixtures (CLAUDE.md rule 4):
a corpus manifest whose `corpus_row_count` is edited behind its recorded
hash, so every quotation of the hash still agrees and only recomputation
over the substance can refuse; the same for the stack; and a forged
benchmark hash quoted consistently by the surface AND every agreement.
Mutations M2–M4 (copy instead of recompute) are caught only by these.

## §3 — Commit 2: the engine, and the limit at whole-run scale

**One stack, read twice.** `FeatureBundle` carries the matrix, its manifest,
the prediction grid, and the stack and corpus manifests — all from ONE
`build_covariate_stack` call — so a grid from a different stack than the
matrix came from is unrepresentable rather than merely refused downstream
(the emitter would refuse it; the bundle means it cannot arise).

**The guard runs before any surface exists.** E2.4's record is emitted,
E2.5's guard evaluated for EVERY design, and only then are surfaces built
and written — marked with the verdict of the design the caller DECLARED.
`claim_design` is a required constructor argument: the guard's unit is
(run, design) (E3.1+2 §3, measured), and the design a claim rests on is a
declaration to record, not a choice for the engine to make. It must be a
design the run executed, checked before a surface is built. The separating
fixture for "the writer got the DECLARED design's verdict and not the
first's": site-out and LOCO fail the same one precondition, so a run
declaring `random_k_fold` (two) is the only case that can tell — and does.

**The whole-run reproducibility test hit the path-hash limit at run scale.**
Two runs of the same engine in different directories differed — in exactly
the fields that quote the stack hash. So the test is two:

| runs | result |
|---|---|
| same DEM path, different output dir | identical `content_hash`; every field outside the excluded set equal |
| same DEM BYTES, different tree | differing top-level set **== `{upstream_hashes, prediction_grid, provenance_chain, output_hashes, surfaces, content_hash}`** — an EQUALITY, so a new field that silently picked up the hash widens it and fails, and the fix collapses it and fails; scores, fold record, verdicts, agreements and surface summaries byte-identical |

That is the E2.4 audit's row M ("15 substance fields reproduce, neither
identity field does") re-measured one phase later and three artifacts
wider, and the BACKLOG entry's Checkpoint-1 prediction demonstrated early
with the same bytes instead of new ones.
