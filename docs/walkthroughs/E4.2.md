## §1 — Commit 1: the footprint rasters

**The grid is the surface's, asserted against the recorded identity.**
`CutoffEconomicModel.apply` now records `grid_identity =
inputs.grid.identity()` at computation, and the writer refuses a grid whose
identity differs, naming the differing keys. The mask is asserted against
the SURFACE's mask exactly (`~isfinite(mu)`), and a footprint that marks a
masked cell minable is refused by name.

**The mask and the footprint are different things.** nodata (NaN) =
UNDEFINED (no covariates); 0.0 = NOT minable with covariates present; 1.0 =
minable. The constructed fixture is what separates them: its raster reads
`[[0, 1, 1, 1], [0, 1, 0, NaN]]` — one NaN, three zeros, four ones — where a
conflating writer would put a 0 at `[1, 3]`. The encoding sentence is in
every file's tags and in the association record.

**The two-reason verdict, per reason, on every file.** `watermark_reason_terrain`
and `watermark_reason_economic_parameters` are SEPARATE tags, each derived
from its own reason's state (never from the combined verdict), beside
`watermark_reasons_unlifted` and the combined `watermark` text. The collapse
observer has both halves: today both tags read UNLIFTED; a Checkpoint-1
fixture (MEASURED DEM) reads `lifted` / `UNLIFTED` — asserted per reason,
not by count — while `data_origin` stays AUTHORED (the lattice's lossy
answer, unchanged; the tags say what moved). Carrier 2, the association
record, carries the same verdict as data.

**The association is machine-resolvable.** The filename
`footprint__<scenario>__<estimator>__z<z>.tif` is readable, and nothing
resolves from it: `economics.footprints.json` maps every basename to its
(kind, scenario, estimator, z, sha256, counts, verdict), and the same facts
sit in each file's tags — the test resolves from the record and checks the
tags agree, parsing no name. `data_origin.yaml` classifies each raster with
its COMPUTED origin, its derivation, and the authorship it INHERITS from
Contract 4 (`author_inherited_from`) — never a new `author:`, which P2.0
does not make available to new work.

**The rasters land in `<out>/economics/`**, their own directory with their
own sidecars, so the surfaces' directory listing — which the manifest's
`output_hashes` is checked against in full — is untouched until E4.3 hashes
the economics block. The first draft wrote them beside the surfaces and the
end-to-end test caught 13 unhashed files: the right test doing its job.

**File inventory (measured):** 12 footprint rasters; `economics.footprints.json`;

## §2 — Commit 2: the scenario difference map

`write_difference` writes one raster per (estimator, z) for each Contract 4
pair, on the same grid, through the same writer. **The code is recomputed
from the two footprints and checked against the difference's own `only_b`
masks** — a difference that disagreed with its inputs is refused, not
written.

**What the map means, in the tags:** *"a SENSITIVITY map, not a resource
map: the area whose minability depends on WHICH PLACEHOLDER CUTOFF IS
ASSUMED"* — `meaning` on every difference file and in the association
record, so a reader who opens the file without this walkthrough meets the
sentence.

**The three-state encoding (plus undefined), kept apart:**

| code | meaning | today |
|---|---|---|
| 0.0 | minable under NEITHER | 0 cells |
| 1.0 | minable under BOTH — case (a) | **2,880 — every unmasked cell** |
| 2.0 | minable under b ONLY — the difference | 0 |
| 3.0 | minable under a ONLY | 0 |
| NaN | undefined (no covariates) — case (c) | 520 |

An all-zeros raster could not tell "no disagreement" from "nothing here";
this one says "both", "neither" and "undefined" as different values, and
the counts sit in the tags (`n_both`, `n_neither`, `n_only_b`, `n_only_a`,
`n_undefined`).

**The measured zero, with its reason:** `difference_fraction_of_predictable
= 0.000000` in every file, because both placeholder cutoffs (10.0, 5.5) sit
below the training mean (19.5 kg/m²) over the whole domain — E4.1's
finding, carried. The real-data test asserts the FULL value set per file
(`{1.0}` over 2,880 cells, 520 NaN), so a change to Contract 4's
placeholders shows as a failure, not a silent improvement. The G4.1 BACKLOG
entry already carries the bracket-nothing ask; nothing here restates it.

**The degeneracy warning, answered.** The constructed fixture — E4.1's 2×4
grid under MARKET and STRATEGIC, in BOTH orders — produces all four codes
plus undefined: `[[2,1,1,1],[0,1,2,NaN]]` and, reversed, `[[3,1,1,1],[0,1,3,NaN]]`.
Its docstring names what each separates: codes 2 separate "computes the
set difference" from "returns empty"; the reversed pair separates b−a from
a−b; `[1,0]` = 0.0 beside `[1,3]` = NaN separates "neither" from
"undefined"; `[0,1]` (exactly at the market cutoff) = 1 separates "both"
from "either". The encoder is also tested alone on hand arrays.
