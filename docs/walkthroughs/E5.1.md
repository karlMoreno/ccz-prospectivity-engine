### The three rules, structural

```text
  runs_root/<run>/run_manifest.json ──► load_run(): finalized · describes itself · EXTENDED · every named file exists
        │                                         (a directory that is not a run is refused BY NAME — never served empty)
        ▼
  GET /runs · /runs/{run_id} · /manifest (the BYTES; ETag = content_hash) · /cv-scores · /ts6-agreement
      /economics · /claim · /layers (commit 2) · /files/{key}  ◄── key looked up in output_hashes BEFORE any path is formed
```

1. **Read-only over the route table.** Only GET handlers exist;
   `test_read_only_is_a_property_of_the_route_table_not_a_convention`
   enumerates `app.routes` — the framework's table, never a list — and
   asserts every method set ⊆ {GET, HEAD}; a POST on a served path is 405
   over the wire. Mutation R1 (a POST route) fails by path and method.
2. **Computes nothing, derives nothing, re-hashes nothing.** Every response
   is a manifest field as recorded or a named file's bytes with the RECORDED
   sha256 as ETag; the test recomputes the hashes, the API never does. The
   one check at load — the manifest describes itself (`compute_content_hash`
   once, the emitter's own rule) — is a refusal condition, not a served
   value. Runs are keyed by the manifest's `run_id`, never the directory
   name (R6).
3. **The files endpoint resolves from the record.** The covariate stack, the
   input rasters and the manifest itself are on disk and "not a recorded
   output"; a dot-dot traversal never reaches the handler (the router resolves
   it to no route). R2 — path first — serves `features/stack/depth.tif` with
   200 and fails.

**What it refuses, each by name** (one test, eight cases): no root; an empty
root; a subdirectory without a manifest; a root that is itself a run; the
committed E2.4 CV-only artifact (NOT EXTENDED — no layers to serve); a
manifest mutated after finalize; a named output file missing; two runs
under one `run_id`. R3/R4/R5 each remove one refusal and fail DID NOT RAISE.

The production run fixture moved to `tests/conftest.py::production_run`
(session scope) — one ~35 s harness run shared by `test_run_harness.py` and
`test_api.py`.

## §2 — Commit 2: the layer catalog (adversarial review)

`GET /runs/{run_id}/layers`, built once at load by `catalog.build_catalog`
from the manifest dict and the association record the manifest names
(`economics.association.file`, hashed in the chain) — no listing, no name
parsed, no raster read, no number computed.

```text
  surfaces[est].rasters.{prediction,uncertainty}  ──► 6 entries, each naming its PAIR
  surfaces[est].mu_min/mu_max · sd_min/sd_max      ──► the legend, min/max only (binning: null, by design)
  surfaces[est].watermark (a string)               ──► watermark_form "surface: one reason"; watermark_reasons None
  economics.rasters[file]                          ──► 18 entries: kind · scenario | pair · estimator · z · sha256
  economics.rasters[file].watermark{terrain, economic_parameters} + scenarios[].watermark.reasons[].cause
                                                   ──► two reasons per entry: lifted · lifted_by · cause
  economics.rasters[file].counts + the record's encodings and difference_meaning ──► the uniformity facts
  claim.verdicts                                   ──► ONCE: failing + passing per design, the watermark beside them
  output_hashes                                    ──► every entry's identity; an entry not hashed is refused
```

### The three shape decisions

**1. Not-applicable is a third state.** `grid.cells` is the naive 72-cell
cross-product (kind × estimator × z × scenario-or-pair), each cell
`present`, `not_applicable` (with `axes_not_applicable` named and, for the
36 surface cells, the `key` it collapses onto) or `absent`. `grid.canonical`
is the 24 cells a control panel should actually offer — one per kind × the
axes that apply to it. The test separates the states with a fixture: one
footprint dropped CONSISTENTLY from the record turns exactly its canonical
cell `absent` (counts 17 / 54 / 1) and touches no inapplicable cell.
Mutation C2 (a two-state grid) reports 54 absent and fails.

**2. The watermark asymmetry is served as recorded.** Each entry names its
`watermark_form`; the catalog says once, in `watermark_asymmetry`, why the
two forms differ. C4 (a second reason invented for surfaces) and C3 (the
two economics reasons collapsed to `any()`) both fail — C3 against the
Checkpoint-1 fixture, where terrain is lifted in every record that carries
it and the catalog must still say `economic_parameters: False` per entry.

**3. The uniformity is explained by served facts.** Every footprint entry
carries `n_minable`, `n_predictable`, `fraction_of_predictable` and the
encoding; every difference entry the five counts, the fraction and the
MEANING sentence ("a SENSITIVITY map, not a resource map"); the catalog
carries `uniformity_today` once with E4.1's reason. All pinned against the
pixels in the test; none computed in the catalog.

**The verdict, once.** The guard's unit is (run, design), never an estimator
or a raster (E3.1+2 §3), so `claim` is served once with `applies_to: every
layer`, both halves per design, and the note that "synthetic" lives in the
watermark field, which is structurally never a precondition. C5 (a blanket
refusal: every precondition in `failing`) fails against a direct
`evaluate_claim` run on the served manifest.

**Explicit exclusions.** `excluded_from_the_catalog` names the six patterns
the listing holds that are not layers — the manifest, the three surface
sidecars, the two origin sidecars, the association record, the nine stack
files — each with a reason. The both-directions test asserts the listing
minus the entries equals exactly the files those patterns match (1+3+2+1+9),
so an implicit exclusion is indistinguishable from an omission only until
this test runs. C6 (the rules dropped) fails.

### The fixtures, and the tamper discipline

`_forged_root` copies the run directory, lets the fixture edit the manifest
dict, the association record and the files TOGETHER, then RE-FINALIZES the
manifest so it describes itself and the API loads it — every derived witness
forged to agree, only the ground truth the test names dissenting:

| fixture | what agrees | what dissents | separates |
|---|---|---|---|
| renamed (`x.tif` in the file, the record, `economics.rasters`, `output_hashes`, the result's `raster_file`) | every record | the coordinates the record carries | resolution from the record vs name-inference (C1 — the parser crashes on a name with no coordinates, which is the failure mode itself) |
| dropped (one footprint out of every record; the file left on disk) | every record | the directory listing | the listing-vs-catalog direction (a vanished layer is caught by the test's other direction, not by the catalog, which must not see the directory) |
| absent (one footprint out of every record AND deleted) | every record | — | `absent` from `not_applicable` |
| Checkpoint 1 (terrain lifted in `economics.rasters`, `scenarios`, the record, `economic_results`, `economic_differences`) | every record | — | per-reason from `any()`/`all()`; surfaces untouched |

**No unreachable check was added.** Everything the catalog could cross-check
(sha256 against `output_hashes`, the record against the manifest) is already
verified by the emitter at emission and sits below that guarantee; the
ground truths in the tests are OUTSIDE the chain — the listing, the pixels,
a direct guard run. The one refusal the catalog makes is an entry not in
`output_hashes`, which no emitter-verified manifest can produce and which
exists so a hand-built manifest cannot catalogue a layer it did not hash.
