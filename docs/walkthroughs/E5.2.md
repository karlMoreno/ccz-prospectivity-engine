## §1 — The format, and the fourth row

```text
  <out>/ordinary_kriging_prediction.tif ┐
  <out>/ordinary_kriging_uncertainty.tif┴─► export/ordinary_kriging.surface.json  {mu[], sd[], grid, source{…}, data_origin, watermark, …}
  <out>/economics/footprint__…__z0.tif  ──► export/footprint__…__z0.json           {values[], grid, source{…}, data_origin, watermark_reasons[…], …}
                                             export/data_origin.yaml                the audit's marker
```

The measured table is in the module docstring and in every surface export's
`why_not_geojson` block. **The fourth row** — masked cells dropped, 100 KB
cheaper on the polygon form — is the failure the format refuses: a masked
cell is `null` at its own index (never 0, never absent), the null set equals
the raster's NaN set exactly (520 cells), and the emitter recomputes both the
values and the null SET from the pixels before recording the file. A count
would not do: a mask shifted by one cell keeps its count and moves its set,
and the fixture that does exactly that is refused by name.

**The pair is one file.** A surface export holds `mu` and `sd` together —
the pairing rule has been structural since E2.1, and a browser that could
fetch a prediction without its uncertainty would be the first place it could
be broken. The catalog's two entries for a surface point at the same file
and name their field (`data_field: mu | sd`).

**A rounding finding, recorded because it looked like a bug and was not.**
The first draft of `_verify_exports` compared an export's arrays against the
in-memory **float64** surface rounded to 3 dp; the export renders the
raster's **float32** pixels. For a value sitting on a rounding boundary the
two differ in the third decimal, and in the extension fixture's 100-tree
forest 1–2 of 2,880 cells did (the e2e run's 40-tree forest happened to have
none — which is why it passed first). The export renders the bytes on disk,
so the emitter now compares against the raster's pixels re-read from the
file, which `_verify_raster` has already shown hold the surface. The
round-trip test's tolerance (half a unit in the third decimal) holds against
the pixels either way; the codes in the economics exports are exact.

## §2 — A derived artifact, carrying what JSON cannot

| carried | from | verified by the emitter against |
|---|---|---|
| `data_origin` | `combine_origins` over the source's computed origin — SYNTHETIC for surfaces, AUTHORED for economics; never declared | the computed surface origin / the raster entry's recorded origin (E5.2 added `data_origin` to `economics.rasters[]`, the value E4.3 recomputes and shows equal to tag, record and result) |
| the watermark, in the source's form | surfaces: ONE reason, a string, `watermark_reasons: null`; economics: TWO reasons per reason with `lifted`, `lifted_by`, `cause`, `watermark: null` | the sidecar's string; the record's reason set and each lifted state — a surface given two reasons, or an economics export with one, is refused by name |
| `source` | the raster basename(s) and sha256 recomputed from the bytes at export time (+ the sidecar's for surfaces) | the rasters' hashes the emitter has itself recomputed |
| `claim_failing_preconditions`, `publishable` | the sidecar (surfaces) / the tags (economics) | — (carried; the catalog serves the verdict once) |
| `grid` | `PredictionGrid.identity()` — the transform and extent the manifest carries | the prediction grid's transform and width |
| `generator`, `determinism_basis` | constants naming the function and what makes it deterministic | — |

**Mutation-verified, the laundering direction first** (§4): an export
declaring MEASURED is refused at the emitter (`export='MEASURED',
computed='SYNTHETIC'`); the exporter mutated to declare MEASURED fails the
test that reads the file. A JSON file is the easiest place to lose
provenance because nothing in the format asks for it; the sidecar, the
source hashes and the emitter's checks are what carry it across.

**Two instrument findings, both acted on.** (i) **X9 survived because the
check was unreachable**: the array check compares the full list with `None`
at NaN positions, so equal arrays have equal null sets and the null-set gate
below it could never fire on its own — the unreachable-check sub-pattern
(CLAUDE.md, ×2 → ×3), in this task's own emitter, found by mutation rather
than by reading. The gate is removed; the array check's message now says
how many differing cells are in the mask (diagnosis, not a second gate);
and the array check gained the fixture only IT can fail on — one unmasked
cell +1.0, the mask intact — because its two existing fixtures both changed
values *and* the mask. (ii) **X1–X8 were every one caught at fixture setup,
not by the test named**: the session's harness run refused the mutated
export at the emitter before any exporter-level test ran (`ERROR`, not
`FAILED`). The reason is examined — the emitter IS the structural guarantee
— and X2′ shows which layer answers when it is silenced: the exporter-level
mask-set test fails on the empty null set. The exporter tests are the
end-to-end observers, not decoration; the emitter is the gate.

Harness: explicit arrays and `set -u`; every mutation confirmed applied;
every restore `cmp`-verified; a run reporting no failures (X9) treated as
