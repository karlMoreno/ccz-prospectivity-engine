## §0 — The decision this task could not proceed past

**There was no JS harness** (0 tracked `.js/.html/.css`, 160 `.py`, no
`package.json`; `node` exists on the machine via Homebrew and is irrelevant
to the repo). The options, measured: **(a) Playwright** — 3 pip packages
plus a ~150–170 MB Chromium download per CI run, on a suite measured
141–378 s; **(b) a Node harness** — adds npm, rejected; **(c) pure Python**
— nothing new, and the DOM, the rendering and the interaction untested.

**Karl chose (c) in one specific form** — the API serves a **presentation
model** (`GET /runs/{id}/viewer`), computed in Python and tested in pytest,
and the page only fetches, builds DOM and draws. The naive (c) — a Python
module for the tests and a JavaScript re-implementation for the page —
would have violated the constraint that matters most: two implementations,
the tests observing the one the user does not see.

**The named exception.** E5.1's rule is "the API computes nothing, derives
nothing, re-hashes nothing" — about DATA. Bins, labels and states are
RENDERING DECISIONS; E5.1 already crossed this line honestly with
`uniform_today` (a derived fact about recorded values, served beside the
counts it compares) and named it as deriving SHAPE, not VALUE. The
requirements, met and recorded in the model's own body: nothing it serves
could be mistaken for a measurement; its binning rule is named
(`binning_rule`: equal-interval, seven bins over the recorded [min, max];
a constant layer gets one); nothing is written back to the catalog
(`legend.binning` stays `null`, asserted). A Playwright smoke test that
skips when Chromium is absent was declined: a test that skips in CI is
coverage-that-isn't wearing a green tick.

**THE MECHANISM'S LIMIT, in those words:** the DOM, the rendering and the
interaction are UNTESTED. A wrong colour drawn, a banner not shown, a
select that does not disable — no test in this repo can fail on it. What
is tested is the function the page consumes, the page's text, and the one
formula the page repeats. **And the limit bit on the first day:** the
page's first draft computed option states itself and labelled a present
layer kind "absent" (it carried every axis value into its probe). No test
could see it; a manual look at a fresh run did. The logic moved into the
model as per-cell **neighbour states** — computed where it is tested — and
the page now looks states up by option index. Recorded as the pattern
predicts, not as a surprise.

**SRI without a network.** The three bundles were fetched from unpkg and
jsdelivr, byte-identical on both, and their sha384 hashes RECORDED in
`services/api/web.py` as tool hashes (the quantile-forest precedent); the
test asserts the page's `integrity` attributes equal them, no network.
Correction to E5.0: 5.24.0's CSS is **70,024 B** (83,195 B was 6.5.0's).

## §1 — Catalog-driven, and where the generality stops

```text
  catalog.grid.axes + axis_labels + value_labels ──► one <select> per declared axis
  catalog.grid.canonical[].neighbours            ──► every option's state: present · not_applicable · absent
  catalog.layers[].legend.ramp / format / min,max ──► bins, colours, number format — per-entry hints
  catalog.layers[].data_url (one file per PAIR)  ──► the arrays; mu AND sd from one fetch
  catalog.training_stations                      ──► the 35 points, origin MEASURED, beside a SYNTHETIC surface
  GET /context                                    ──► geometry that is not a run artifact, its own origin + citation
```

The page names **no layer type, no model name, no axis, no unit** of this
project — `tests/test_viewer_model.py` greps the model module and the page
for twelve such names and fails if one appears (mutation V4). The
flexibility requirement's only real test builds a model from a FOREIGN
catalog (axes `quantity × probe × season`, layer types `temperature` /
`ice_fraction`, unit K) with no code change — **and it tests a FUNCTION,
not a rendered panel** (§0).

**The honest boundary — Karl's phrase, carried into BACKLOG §3:** *the
viewer is catalog-driven; the catalog is not yet data-driven.* `catalog.py`'s
`KINDS`, `APPLICABLE_AXES`, the ramp/format and label tables are this
project's constants; a five-axis dataset needs an E5.1 change, not a viewer
change. Not generalized speculatively; the entry's trigger is the first
second dataset. **What still needs a per-layer hint:** which ramp and how
to format a value — now catalog data (`legend.ramp`, `legend.format`, the
E5.1 commit reported before this task's commit 1), so a new layer type
renders with its declared hint or not at all, never silently with a default.

## §2 — Commit 1: the map and the controls

**No tile basemap** (Karl's decision 3). Measured: zero Natural Earth 110m
coastline features intersect the study extent (nearest coast 10.4° away;
five in the whole CCZ box). A basemap here renders ocean and buys an uptime
dependency, a licence and a runtime fetch. The page draws a dark
background, a 5° graticule and the vendored public-domain coastline
(139,907 B, sha256 recorded, cited in the footer and beside its checkbox).
BACKLOG §7's basemap sub-point is closed, not deferred.

**Three states, three treatments.** Over the naive 72 cells 18 present +
54 not-applicable + 0 absent; over the 24 canonical cells all present
(E5.1's count). The model labels them `available` / `not an axis of this
layer` / `no artifact for this combination`, and the page gives each its
own option class (mutation V3: two states with one label fails). Inapplicable
axes are greyed with that label; an absent value would be struck through
with the other.

**The readout** shows the value, its paired half from the SAME export file
(E5.2's pair), the paired half's SEMANTICS string (three estimators, three
kinds of sd — the string travels with the number), lon/lat and row/col.
**Masked cells** are a hatched grey in no ramp and not the background
(mutation V1). **The eighteen uniform rasters** show a banner with the
catalog's explanation and E4.1's reason. **No timeline.**

**Pins:** maplibre-gl 5.24.0 (BSD-3-Clause; the last UMD build, 1,056,837 B
JS + 70,024 B CSS) and deck.gl 9.3.10 (MIT, 1,648,135 B), exact versions,
`integrity` + `crossorigin`, the page's only external references.

## §3 — Commit 2: context layers

A second class of layer, served apart from every run (`GET /context`,
`/context/{id}`), never a catalog entry — a registry entry carrying a
watermark, reasons, a claim or coordinates is refused by name at startup
(mutation K1), every file's sha256 is checked against its record (K2), and
a GeoJSON that declares an origin in-file must declare the registry's (K3).
Outline only (K5: a fill fails). The citation is beside the checkbox and
in the footer. Three states: shown / hidden (off is not gone) /
unavailable.

**The fixture says it is one:** a rectangle at the CCZ management area's
published approximate extent, declared AUTHORED in-file with `author:
model`, titled FIXTURE — a fabricated look-alike would be the placeholder
this project unwired twice. **The scale surprise, measured and kept:** the
CCZ box ≈ 13.86 M km², the prediction extent ≈ 0.41 M km² — **33.8×**; the
study area is **2.96 %** of the zone, and the view is not adjusted to hide
it. **The real data is a separate task** (BACKLOG §3): Marine Regions
MRGID 64222 (CC-BY 4.0), the ISA shapefiles (ISA copyright; ISBA/17/LTC/7,
ISBA/18/C/22, ISBA/26/C/58, ISBA/26/C/43) — under `data/context/`, inside
the audit's walk, declaring in-file — with two decisions riding on it that
are Karl's: whether the CCZ polygon resolves the AOI (and whether a hashed
download from an authoritative publisher is MEASURED rather than the
LITERATURE the AOI entry assumes), and whether the APEIs populate
`exclusions.geojson`.

## §4 — Commit 3: the stations, and what the map argues

The 35 stations come from the manifest's `training_stations` (E5.5) through
the model — never the corpus CSV (mutation V7: a page fetching it fails).
They are drawn over every surface layer as white outlined points in a
colour no ramp uses; the legend row names BOTH origins (*35 training
stations — origin MEASURED (the surface is SYNTHETIC)* — mutation S1: one
origin fails); a station is pickable and reads as a PLACE (id, lon, lat,
origin) with no value field. The clustering — two groups ~991 km apart,
zero pairs between 13 and 986 km — is VISIBLE as drawn points; the number
is not computed by the model (that would be a measurement at the API) and
stays the derive-vs-record question E5.5's BACKLOG entry holds for E5.4.

## §5 — The first non-Python files, and what the audit sees

`apps/web/index.html`, the vendored coastline and the fixture are the first
non-Python files in the repo. **Confirmed, not assumed** (a test runs
`git ls-files -- data tests/fixtures`): none is in the walk, and the walk
holds no `.html/.js/.css`. `index.html` is the first artifact with **no
provenance chain** — it is a TOOL, and what it DISPLAYS carries the
provenance. The corollary for E5.4: a viewer bug corrupts presentation,
not artifacts, which is exactly why the honesty surface must be tested at
the data layer (the model) rather than trusted at the pixel layer.
