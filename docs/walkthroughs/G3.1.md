## 2. Where the script landed, and the convention

delivered copy).

The three bulk outputs (`*.npy`, the cells CSV) and the preview PNG stay under

## 3. Contract 6's declared output — derived, not assumed

The contract declares `raster: data/ts6/ts6_abundance.tif` and the digitization
produced `.npy` arrays. Both facts come from the artifacts: a GeoTIFF was needed
and did not exist.

**The affine was verified against the arrays rather than trusted.** The sidecar's
`gdal_geotransform` is `[-160.0, 0.1, 0.0, 20.0, 0.0, -0.1]` with `width: 500`,
`height: 200`. Checked three ways before writing:

- the arrays' shape is `(200, 500)` — matches `height × width`;
- `west + width × 0.1 = -110.0`, which is the script's own `LON1`;
- `north + height × (-0.1) = 0.0`, which is the script's own `LAT1`.

The transform therefore agrees with both the array shape *and* the graticule the
script measured, independently. Written as single-band float32, EPSG:4326, NaN
nodata, deflate — 7,569 bytes, read back with 29,252 finite cells equal to the
midpoint array. **Not larger than this task:** `rasterio` is already a dependency
and `FileTS6Reference` already loads a TS-6 raster from a path with a declared
origin, so no new seam was needed.

**What the raster carries, and the honesty cost:** class **midpoints**. The figure
offers intervals, not values; the midpoint assignment is a choice, which is exactly
what `digitization_uncertainty` now records.
